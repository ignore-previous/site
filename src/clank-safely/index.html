Clank Safely

Set up Claude Code or Codex so it can't do more than you meant. This page names the official settings, quotes the docs, and says which ones the tool enforces and which are only advice. It changes nothing on your computer. OpenAI and Anthropic didn't write or review it.

On Windows: Claude Code's sandbox runs only inside WSL2. Without it, your permission rules are the only fence.

What this page is, and is not

This page is advice with sources. It blocks nothing.

Where a setting is enforced, Claude Code or Codex enforces it, and we say which. The page is for someone who has already installed Claude Code or Codex and approved a few prompts. It covers Claude Code on Windows first, then the Codex settings.

Or let your agent walk you through it

Paste this prompt into Claude Code, Codex or Cursor, opened in your project's folder. The agent reads this page, checks your settings first, then asks you one question at a time. It shows each settings change and writes it only when you say yes. In claude.ai or ChatGPT, it gives advice only.

Please help me set up my coding agent safely, using the Clank Safely guide from Ignore Previous.

Rules:
1. First read the guide: https://ignoreprevious.dev/clank-safely/index.html.md
   Use its setting names and its sources. If you're not sure a setting exists, say so.
2. Install nothing except What's Allowed (the npm package whatsallowed), which npx downloads when it runs. If you can run commands, start by checking my current settings with What's Allowed: npx whatsallowed, in this project's folder. Show me the command and wait for my yes before you run it.
3. Ask me one question at a time, and wait for my answer.
4. Before you run a command or change any file, show me the exact command or change. Do it only after I say yes.
5. Don't open or print .env files, keys or other secret files. If something points to one, give me the file name only.
6. If you're a chat app such as claude.ai or ChatGPT and can't change my files, give advice only. I'll make the changes myself.
7. At the end, list every file you changed and how to undo each change.

The agent's own settings still decide what it may do. The prompt asks it to check with you, but it can't force it to.

Step 2: turn on the protections your agent already has

Enforced Enforced by Claude Code or Codex.

Both tools have protections built in. This step names the settings in the words the official docs use. Below are three ways of working: Cautious, Balanced and Unattended. Each is a heading we use to explain a trade-off. None is a setting, and there is no one-click switch. You change the settings yourself, in the files or menus the docs describe.

In Claude Code, settings live in JSON files. Your own file is ~/.claude/settings.json and a project's is .claude/settings.json. A managed file, set by an administrator, wins over both Source. In Codex, your own file is ~/.codex/config.toml. A project's .codex/config.toml is read only for projects you have marked as trusted Source.

A few terms first. A permission mode is how often Claude Code asks you before acting. A rule allows or blocks one kind of action. A sandbox is a fence the operating system puts around the agent's commands, so they can touch only some files and some network addresses. An approval policy is Codex's name for how often it asks.

Cautious

Suits: you are new to agents, or the files matter (client work, or anything with passwords or keys), or you want to see each step.

Trade-off: you get asked more often, but not before every action. Claude Code's default mode "prompts for permission on first use of each tool." Its plan mode reads files and runs read-only shell commands, and doesn't edit your source files Source. Codex's two docs pages disagree on what its read-only mode runs without asking, so see the Codex settings below. Many prompts can tempt you to approve without reading. Our tip We recommend you read each one.

Claude Code

  • permissions.defaultMode set to default. Claude Code "prompts for permission on first use of each tool." Enforced Source
  • permissions.defaultMode set to plan, for a first look at a project. Claude "reads files and runs read-only shell commands to explore but doesn't edit your source files." Enforced Source
  • permissions.deny rules. A deny rule blocks one kind of action. For example, a Read rule for ./.env stops Claude's file tools, and the file commands Claude Code recognises (such as cat), from reading a file of secrets. The docs say it does not cover every command that could read the file. For that, they point to the sandbox (see Balanced). Read rules use gitignore-style paths. An allow rule "can't carve an exception out of a deny rule." Enforced Source
  • permissions.disableBypassPermissionsMode set to "disable", so the mode that skips prompts cannot be turned on. permissions.disableAutoMode does the same for auto mode. Enforced Source

Codex

  • sandbox_mode has three values: read-only, workspace-write and danger-full-access. Enforced Source
  • For this way of working, we recommend sandbox_mode = "read-only". Our tip The docs say that in this mode "The agent can inspect files, but it can't edit files or run commands without approval." Enforced Source The approvals page describes it a little differently: "Codex can read files and run commands within the read-only sandbox." Which commands run without asking in this mode: Pages disagree Not confirmed The two pages do not agree. We recommend you test it before you rely on it Source.
  • approval_policy = "on-request". Commands the sandbox permits run without prompting, and the docs say "Codex asks for approval to edit files outside the workspace or to run commands that require network access." Enforced Source

Balanced

Suits: everyday work on your own project, where you review the result before you rely on it.

Trade-off: fewer prompts, because edits inside the project are approved for you and, where the sandbox runs, it fences the commands. An allow rule that is too wide removes the protection it was meant to give, so we recommend narrow allow rules.

Claude Code

  • permissions.defaultMode set to acceptEdits. It "automatically accepts file edits and common filesystem commands such as mkdir, touch, mv, and cp for paths in the working directory or additionalDirectories." We recommend you keep additionalDirectories short. Enforced Source
  • permissions.allow rules, one for each command you trust. A rule of Bash or Bash(*) on its own matches every command, and rules that limit a command's arguments are fragile. Rules are checked in the order deny, then ask, then allow. Enforced Source
  • permissions.deny rules for secrets files, as under Cautious. Enforced Source
  • The sandbox. The docs say sandboxing "provides OS-level enforcement that restricts shell commands' filesystem and network access." With the sandbox on and autoAllowBashIfSandboxed at its default of true, "the sandbox boundary substitutes for that whole-tool prompt." Enforced Source
  • The sandbox is off by default. Turn it on with the /sandbox command in a session, or set sandbox.enabled to true in ~/.claude/settings.json. To add folders it may write to, use sandbox.filesystem.allowWrite. To block paths, use sandbox.filesystem.denyWrite and sandbox.filesystem.denyRead. For sites, use sandbox.network.allowedDomains and sandbox.network.deniedDomains. Enforced Source Source
  • The sandbox does not run on native Windows. The docs say "On native Windows, Claude Code runs commands unsandboxed." It runs on macOS, Linux and WSL2 (Windows Subsystem for Linux 2), so on a Windows computer you would run Claude Code inside WSL2 to use it. Without it, nothing fences the commands, so we recommend you keep your rules narrow. Guidance Source

Codex

  • sandbox_mode = "workspace-write" with approval_policy = "on-request". Our tip We recommend this pairing. Each setting is Enforced Source
  • The docs say Codex "uses an OS-enforced sandbox that limits what it can touch (typically to the current workspace)." On macOS it uses Seatbelt, and on Linux bwrap plus seccomp. Enforced Source
  • On Windows, Codex has its own sandbox. The windows.sandbox setting picks one of three: mxc, which the docs recommend on compatible devices, or elevated and unelevated, which are fallbacks. The unelevated one has weaker network isolation. Inside WSL2, Codex uses the Linux sandbox. Enforced Source
  • "By default, the agent runs with network access turned off." Enforced Source
  • The folders .git, .agents, .codex and .aws inside a writable folder are protected as read-only. Enforced Source

Unattended

Suits: a long job you leave running while you do something else. Our tip We recommend you only do this in an isolated place: a separate computer or a virtual machine, holding a copy of the project and none of your real passwords or personal files.

Trade-off: the agent can do a lot without asking, so the fence around it does the protecting. If the fence is weak, a mistake or a prompt injection can do real harm. A prompt injection is hidden text in a web page or file that tells the agent to do something you did not ask for.

Claude Code

  • permissions.defaultMode set to auto. It "runs without routine prompts; before actions such as shell commands and network requests run, a background classifier checks that they align with your request." A classifier is a program that labels each action as fine or not fine. Enforced Source Not confirmed Whether auto mode is available on your plan or model was not checked, so it may not be on for you.
  • permissions.defaultMode set to dontAsk. It "auto-denies every call that would otherwise prompt." Actions that need no approval still run, such as file reads in your working directories and tools you pre-approved with permissions.allow rules. Two exceptions are noted below the list. Our tip We recommend you pair it with a short permissions.allow list. Enforced Source
  • bypassPermissions skips permission prompts "except for the actions no mode auto-approves". The docs warn that it skips them even for "writes to protected paths such as .git and .claude". Those folders hold your project's history and Claude Code's own settings. We recommend you use it only inside the isolated place described above. Enforced Source
  • auto and bypassPermissions do not take effect when set in a project's or local settings file, only in your own or a managed one. Enforced Source
  • We recommend you keep the sandbox (on Windows, that means WSL2) and your deny rules on. The docs say sandbox restrictions "still apply even if a prompt injection bypasses Claude's decision-making." Enforced Source

Two exceptions to dontAsk. A mod you installed (an add-on for Claude Code) can still approve some calls this mode would deny. And a few tools are denied even if you allowed them, such as tools that need you to answer a question. So this mode does not promise that only the actions you listed can happen. Source

Codex

  • approval_policy = "never" means "The agent doesn't stop for approval prompts." It works with every sandbox mode, and Codex makes "a best effort within the constraints you set". Our tip We recommend you pair it with sandbox_mode = "workspace-write", so the sandbox still fences the work. Enforced Source Source
  • We recommend you avoid sandbox_mode = "danger-full-access". The docs say that in this mode "The agent runs without sandbox restrictions", which removes the filesystem and network boundaries. Enforced Source
  • Network access is off by default. To turn it on, set network_access = true under [sandbox_workspace_write]. To limit it to chosen sites, use the network proxy, a go-between program that decides which sites a command can reach. Also set enabled = true under [features.network_proxy] and list the sites in domains, each marked "allow" or "deny". The docs say deny "always wins over allow". That proxy covers commands only. The docs say it does not filter web search, app tool calls or MCP (Model Context Protocol, a standard way to link an AI tool to other programs) server connections. Enforced Source

If an administrator manages your computer

An administrator can set rules that you and your projects cannot override. In Claude Code these are managed settings. The docs say "no other level, including command line arguments, can override a managed permission rule." The setting allowManagedPermissionRulesOnly "makes managed settings the only settings source of permission rules." Enforced Source

We recommend you leave those files alone and ask your administrator.

What this does not tell you

This page shows what your setup allows. It doesn't prove your setup is safe.

No setting makes an agent safe on its own. The aim is modest: leave it able to do less than it could, and know what it can do.

Using ChatGPT or Claude in a browser or app? Their memory and training are account settings, which What's Allowed can't read Our docs. What Can My AI See? covers them.
